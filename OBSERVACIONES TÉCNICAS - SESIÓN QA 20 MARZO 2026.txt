1. OBJETIVO

Implementar un flujo de navegación consistente en todos los mantenedores donde:
- El ID nunca aparezca en la URL
- Los mensajes de éxito/error muestren el nombre del registro
- Las redirecciones después de crear/editar vayan a la página "Ver"
- El sidebar esté visible en todas las páginas


2. CAMBIOS EN LA ARQUITECTURA DE URLs
--------------------------------------------------------------------------------

2.1. Archivo: menu.php
------------------------
Cambios realizados:
- Aceptar parámetro "page" desde POST además de GET
- Preservar parámetros adicionales (id, idPais, idRegion, etc.) para los archivos incluidos
- Asignar parámetros POST a $_GET y $_REQUEST para que estén disponibles en las páginas hijas

Código agregado:
```php
// Aceptar page desde POST
$page = $_GET['page'] ?? $_POST['page'] ?? '';

// Preservar parámetros adicionales
foreach ($_POST as $key => $value) {
    if ($key !== 'page') {
        $_GET[$key] = $value;
        $_REQUEST[$key] = $value;
    }
}

PROBLEMAS RESUELTOS

Problema	Solución
ID visible en URL	Cambio de GET a POST en botones y redirecciones
Mensajes sin nombre	Obtener nombre antes de operación BD
Exportaciones solo página activa	Usar filas=-1 en exportaciones
PDF mostraba '—' en columna Tienda	Convertir ✅/❌ a "Sí"/"No"
Error 1062 mostraba "0" en listado	Manejo específico de error duplicado
Sidebar no visible en páginas crear	Cargar páginas a través de menu.php
Conversión GET→POST en vistas	Redirección automática en ver_*.php
