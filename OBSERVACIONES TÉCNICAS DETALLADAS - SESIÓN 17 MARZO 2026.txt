2. PROBLEMAS DETECTADOS Y SOLUCIONADOS
--------------------------------------------------------------------------------

2.1. Validaciones inexistentes o dispersas
     • Problema: No había un sistema central de validaciones
     • Solución: Creación de archivos validaciones.php y validaciones.js
     • Beneficio: Todas las validaciones en un solo lugar, fáciles de mantener

2.2. Zona horaria inconsistente entre entornos
     • Localhost: America/Santiago (UTC-3)
     • Servidor: America/Chicago (UTC-5)
     • Solución: Detección automática de entorno en producto-ver.php
     • Código: if ($es_localhost) { ... } else { convertir Chicago → Chile }

2.3. Exportación a Excel con formato incorrecto
     • Problema: Los números se convertían a decimales (1.200 → 1.2)
     • Solución: Generación de archivo XLS con HTML en lugar de CSV
     • Archivo: exportar_excel.php con estilos CSS incluidos

2.4. Filtro de categorías no funcionaba
     • Problema: El evento change del select no se disparaba
     • Solución: Reemplazo del select por uno nuevo con event listeners
     • Archivo: components/tabla_pro/tabla_pro.js

2.5. Página en blanco al crear productos en localhost
     • Problema: Estructura de tabla productos inconsistente
     • Solución: Corrección de tipos de datos y columna fecha_creacion
     • SQL: ALTER TABLE productos MODIFY COLUMN fecha_creacion DATETIME

2.6. Columna 'Tienda' no aparecía en Excel
     • Problema: Los iconos ✅ se eliminaban antes de la conversión
     • Solución: exportar_excel.php ahora convierte ✅ → "Sí" y ❌ → "No"

2.7. URLs no se validaban en categorías
     • Problema: No había validación para URLs de imágenes
     • Solución: Agregadas funciones validarURLImagen() y sanitizarURL()
     • Archivos: validaciones.php, validaciones.js, categoria-*.php

5. CORRECCIÓN DE ZONA HORARIA
--------------------------------------------------------------------------------

5.1. Diagnóstico:
     • Localhost: America/Santiago (UTC-3)
     • Servidor: America/Chicago (UTC-5)
     • MySQL en servidor guardaba fechas en hora Chicago

5.2. Soluciones aplicadas:
     • SQL: SET GLOBAL time_zone = '-03:00'
     • SQL: SET time_zone = '-03:00'
     • PHP: Detección automática de entorno en producto-ver.php
     • PHP: Conversión condicional (Chicago → Chile solo en servidor)

5.3. Código implementado:
```php
$es_localhost = ($_SERVER['HTTP_HOST'] == 'localhost' || $_SERVER['HTTP_HOST'] == '127.0.0.1');
if ($es_localhost) {
    $fecha = new DateTime($fecha_bd);
} else {
    $fecha = new DateTime($fecha_bd, new DateTimeZone('America/Chicago'));
    $fecha->setTimezone(new DateTimeZone('America/Santiago'));
}
