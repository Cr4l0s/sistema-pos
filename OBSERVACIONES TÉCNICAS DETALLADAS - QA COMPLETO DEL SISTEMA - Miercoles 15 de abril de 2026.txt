----------

- Se eliminaron los países duplicados (9, 31, 202, 208, 214, 215, 216)
- Se activó Chile (vigente = 1)

SQL UTILIZADO:
UPDATE regiones SET idPais = 1 WHERE idPais IN (9,31,202,208,214,215,216);
DELETE FROM paises WHERE idPais IN (9,31,202,208,214,215,216);
UPDATE paises SET vigente = 1 WHERE idPais = 1;

1.2 REGIONES
------------
PROBLEMA DETECTADO:
- 51 regiones cuando Chile solo tiene 16 (cada región repetida 3-4 veces)
- Región Metropolitana duplicada (ids: 7, 29, 45)
- Regiones extras: "Aysén" (id 17) y "región de prueba" (id 22)

SOLUCIÓN APLICADA:
- Se eliminaron regiones duplicadas manteniendo la de menor idRegion
- Se consolidó la Región Metropolitana en idRegion = 7
- Se eliminaron regiones extras
- Resultado final: 16 regiones únicas

SQL UTILIZADO:
DELETE r1 FROM regiones r1
INNER JOIN regiones r2 
WHERE r1.idRegion > r2.idRegion 
  AND r1.nombreRegion = r2.nombreRegion
  AND r1.idPais = r2.idPais;

5.1 Tabla de relación usuarios_paises
--------------------------------------
Se creó la tabla para asociar países a usuarios:

CREATE TABLE usuarios_paises (
    idUsuario INT NOT NULL,
    idPais INT NOT NULL,
    fecha_asignacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (idUsuario, idPais),
    FOREIGN KEY (idUsuario) REFERENCES usuarios(idUsuario) ON DELETE CASCADE,
    FOREIGN KEY (idPais) REFERENCES paises(idPais) ON DELETE CASCADE
);
